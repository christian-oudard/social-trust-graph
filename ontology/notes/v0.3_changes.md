# v0.2 → v0.3: review round 2 and dispositions

Four fresh reviews of v0.2 were run: minimality, formal, red team and brief compliance.
Their texts are in `notes/review2_*.md`. Every exploit and bug was reproduced before it
was acted on, and each is now a regression scenario (`x5`, `x6`, plus edits to `s1`–`s6`
and `x1`–`x4`).

## Coalesced (fewer primitives, same tested behaviour)

| Change | From |
|---|---|
| Capacities 4 → 2: *owe* (bear duties, own one's conduct, answer) and *claim* (hold rights, confer powers) | minimality E1: under the three hypotheses, owe ≡ answer and claim ≡ empower |
| The `merge` edge kind removed: a merge is `feeds` (knowledge, never authority) | E6 |
| `reparation` derived from `trigger` | E2 |
| Forgetting by reversion removed. Only a sanitization warranty cuts knowledge, so content equality no longer enters deontics outside pins | E3 |
| Sanitization is a plain warranty on `disclose X`; the `carry` convention is gone | E5 |
| `act` is no longer counted as a sort: four sorts plus a vocabulary | minimality |
| Warranty of authority removed: the registry makes scope public, so reliance on an out-of-scope promise is never reasonable | red team Y2 and our analysis; replaces 3 rules and a defection rule |

## Sharpened (replaced something weaker)

| Change | Finding |
|---|---|
| **Answerability is coverage; authority is coverage within scope.** Copies, and feeds into invocations no person or org acts for, pass answerability on. It spreads only down lineage edges | Y3 scope immunity, Y4 laundering by feed, Y5 framing, F4 |
| Securities have a holder (`creditor`). They are irrevocable directly and by cascade, end once the breach is repaired, only perform (never create commitments, never make the grantor answer for other conduct), and inherit no pins | Y1, Y2, Y10, F8, F9 |
| Vitiation of every registry act: an invocation steered by someone it does not act for cannot create, release, revoke or appoint. A creditor-induced breach of an avoid or warranty is excused. Performance is never excused | Y6, F6, F7 |
| Dual-agent releases void | Y6(d) |
| Delegation cites its parent (`under`) when the creator holds several candidate authorities | C1 counterexample at larger bounds, F13 |
| The root exception for followed kinds is keyed on recognition, not on scope `all`. Role powers need the holder's own authority. Amountless acts pass only cap-0 scopes | Y7, F5 |
| Appointment is an act (`appoints`), replacing unauthored `fills`. Every role has an appointer | minimality, brief, Y9 |
| External drift is its maker's act (`changed_by`). "Do not swap without notice" binds the vendor who swaps | brief compliance |
| **Resolutive conditions** (`until`) terminate a commitment, as opposed to pins, which make it dormant | brief compliance: "must not survive" was only dormant |
| Succession needs the predecessor's *own* custody, and is timed from the successor's recognition | F10, F11 |
| No self-assurance. A warranty owed by an office is broken by its holders | F14, and a surviving mutant |
| Persons: content is one opaque self slot. Only self slots cannot be copied, so API models can fork. Deadlines within the horizon; a commitment is created once | brief, Y11, F12 |

## Verification

* **Mutation testing** deletes every statement of the core in turn and adds 42 semantic
  mutants. 199/199 are killed. v0.2 claimed "every rule is mutation-tested", but 21
  deletions went unnoticed.
* **Exhaustive checks** use a generator that now includes warranties, securities, feeds,
  injection, resolutive conditions, external changes, appointments and citations. They
  run by default at 5 invocations, 3 instruments and 3 commitments, and are UNSAT up to
  6, 4 and 3.
* **The Rust cross-check** runs clingo with the type discipline. It covers every scenario,
  rich witness worlds from each check, and random worlds, under all three hypotheses.
